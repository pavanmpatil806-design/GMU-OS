==================================================================
GMU OS 64  --  64-bit UEFI edition of MikeOS (GM University, 2026)
==================================================================

WHAT CHANGED vs. THE 16-BIT VERSION
  * kernel is a 64-bit UEFI application (BOOTX64.EFI), runs in long mode
  * no BIOS: screen = UEFI text console, keyboard = UEFI input,
    files = UEFI file system (boots from the USB stick's FAT32 volume)
  * same os_* system calls and register conventions (pointers are 64-bit)
  * command history: Up/Down arrows recall the last 16 commands
  * several pendrives: DIR shows only the boot pendrive; DIR USB lists the
    files of every OTHER USB drive as USB1:NAME, USB2:NAME ...
    Any file command accepts these names:  CAT USB1:A.TXT, SIZE, DEL, REN,
    COPY USB1:A.TXT B.TXT, COPY A.TXT USB1:A.TXT, COPY USB1:A.TXT USB2:A.TXT
    COPY USB1:A.TXT then PASTE (same name on the boot drive) or PASTE USB2:
    (same name on pendrive 2). BOOT:NAME means the boot pendrive.
    DIR USB + arrow keys + Enter copies the highlighted file to the clipboard.
    Use names without spaces: USB2:FILE.TXT (not 'usb 2').
    System Volume Information and $ folders are hidden.
    The other pendrives must be FAT32/FAT16 (UEFI cannot read NTFS/exFAT).
  * features/cli.asm: same commands, same messages, same behaviour
      EXIT HELP GMUINFO ABOUT CAL CLS DIR LS VER TIME DATE PBL
      CAT DEL COPY REN SIZE  + running programs by name
  * new: SHUTDOWN (power off), PASTE, COPY <file> (clipboard),
    DIR lets you pick a file with the arrow keys (Enter = pick, Esc = skip),
    then COPY (no name) + PASTE [newname]; PASTE EFI/X.TXT goes into a folder
  * programs: 64-bit flat binaries starting with 'GMU64BIN'
    (see programs/hello64.asm and programs/mikedev64.inc)

NOT PORTED YET (still 16-bit only)
  * BASIC interpreter (basic.asm) and the .BAS programs
  * the old 16-bit .BIN programs (edit, forth, ...): real-mode code
    cannot run in 64-bit mode; they need to be rewritten per program
  * os_dump_string / os_dump_registers / os_run_basic (return an error)
  * LS no longer shows the "first cluster" column (UEFI has no cluster info)

FILES
  build.sh / buildwin.bat   build with NASM only (Linux/WSL, Windows)
  make-image.sh             create build/gmuos64.img (GPT + FAT32)
  run-qemu.sh / .bat        start in QEMU with UEFI firmware (OVMF)
  usb_files/                copy the CONTENTS of this folder to a USB stick
  build/gmuos64.img         ready-made disk image (QEMU, or write to USB)
  firmware/OVMF.fd          UEFI firmware for QEMU (EDK2, BSD license)
  source/kernel.asm         PE header + entry + main flow (was kernel.asm)
  source/features/*.asm     screen, keyboard, string, disk, cli ... (64-bit)

DESKTOP  (Phase 1 of the graphical interface)
  GMU OS now starts with a graphical desktop (wallpaper, icons on the left,
  taskbar with start button / search box / clock, start menu, mouse pointer).
  It runs from the boot pendrive only; Windows is only used to copy files.
  * Mouse: move, click an icon to select it, double-click to open it,
    click the G button for the start menu.
  * Keyboard (always works): arrow keys move the pointer, Tab jumps to the
    next clickable item, Enter clicks/opens, Esc closes a menu or window.
  * Terminal icon = the command line (type EXIT to come back to the desktop).
    C Compiler icon = the C editor.  Start menu > Shut Down powers off.
  * Other icons (My Computer, Documents, File Manager, ...) show a
    "next phase" window for now.
  * The desktop picks a 1280x720 screen mode when the PC offers it.
  * If the desktop cannot start, or a file called NOGUI.TXT is on the
    pendrive, the old text interface starts instead.
  * The line at the bottom right of the wallpaper says whether the mouse was
    found.  Some PCs (some touchpads) do not give a mouse to the firmware;
    the keyboard controls above still work.
  * The artwork (fonts, icons, wallpaper) is generated by tools/gen_assets.py
    (needs Python, Pillow, numpy); the generated files are in source/assets/.

PRINTER  (USB printers)
  The OS detects a USB printer by itself (a printer icon appears in the
  taskbar) and can print text files.
  * Desktop: Printer icon (or Start menu > Printer) > "Print a file" > click
    a file > Print.  Files on other USB drives are listed as USB1:NAME.
    Refresh looks for the printer again.
  * Command line:  PRINTER          show the detected printer and its language
                   PRINT FILE.TXT   print a file
                   PRINT            print the file picked with DIR + arrow keys
  * The printer's name and supported languages are read from the printer
    itself.  Text is sent as PCL (HP and most laser printers), as a small
    PostScript program, or as plain text, depending on what the printer says.
  * Limits: USB printers only; files up to 256 KB; plain text files (not
    PDF, Word or images).  Cheap "host-based"/GDI inkjets that only work with
    a Windows driver cannot print this way.
  * This code could only be tested with simulated devices, not with a real
    printer.  If printing fails, the message tells you what the printer did.

SCREEN FIX
  The desktop re-checks the screen mode every time it redraws, which fixes the
  striped/sheared screen some laptops showed after leaving the Terminal or
  the C editor.

C COMPILER  (command: CC FILE.C)
  CC compiles a C program to bytecode and runs it inside GMU OS.
  Examples on this stick: CC HELLO.C, CC NUMBERS.C, CC CONTROL.C,
  CC GLOBALS.C, CC SORT.C, CC HANOI.C, CC CHARS.C, CC MEDIUM.C, CC PERF.C
  CC USB1:SORT.C runs a program that is on the second pendrive.
  Supported: int/char/void, globals, local and global int arrays (with
  {...} initial values), functions with parameters and recursion,
  if/else, while, for (with int declarations), break, continue, return,
  + - * / % << >> & | ^ ! ~ == != < <= > >= && || ?: , ++ -- += -= *= /= %=,
  // and /* */ comments, #include lines (ignored).
  Builtins: printf (%d %i %x %c %s %% and a width such as %5d),
  putchar, puts, getchar, exit.
  Not supported yet: pointers, char arrays, string variables, structs,
  floats, switch, do-while, goto, #define, multiple files.
  Errors are reported as "CC: line N: message" (compile) or
  "RUNTIME ERROR: ..." (run time, e.g. division by zero, array index).
  Speed: a few thousand calls per second in an emulator; real PCs are
  much faster.

C EDITOR  (command: C)
  Type C code directly in the OS:
    C             open the editor (the text is kept when you press Esc)
    C FILE.C      open an existing file in the editor
    CC            same as C
  Keys:  Enter = compile and run the program
         Shift+Enter = new line (auto-indent; '}' steps back)
         Arrows, Home, End, PgUp, PgDn, Backspace, Delete = edit
         F2 = save to a file     F3 = new (clear text)     Esc = leave
  After the program finishes, press a key to return to the editor.
  If a PC's keyboard cannot report Shift, the Tab key is the new-line key.

BOOT FROM A USB STICK (Windows)
  1. Format the stick as FAT32 (right click > Format > FAT32).
  2. Copy everything inside usb_files\ to the ROOT of the stick, so that
     this file exists:   E:\EFI\BOOT\BOOTX64.EFI
  3. Restart the PC, open the boot menu (F12 / F10 / F9 / Esc, depends on
     the maker) and choose the entry starting with "UEFI: <your USB stick>".
  4. Secure Boot must be OFF (BIOS setup > Security/Boot), because
     BOOTX64.EFI is not signed.
  Alternative: write build\gmuos64.img with Rufus ("DD Image" mode) or
  balenaEtcher.  This ERASES the stick.

BOOT IN QEMU
  Linux/WSL:   ./run-qemu.sh
  Windows:     run-qemu.bat   (QEMU for Windows installed)
  or:          qemu-system-x86_64 -machine q35 -m 256 -bios firmware/OVMF.fd
                 -drive format=raw,file=build/gmuos64.img
